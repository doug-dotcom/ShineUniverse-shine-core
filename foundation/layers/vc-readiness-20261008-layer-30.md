## Evidence boundary and ownership

This is offline-synthetic source integration evidence, not a real signed AI request, authenticated L session, Supabase database proof or deployed consumer route. All auth, identity mapping, permission projections, AI policy/proposal verification, private registry, read adapter, recipient and durable-task projections are synthetic in-memory adapters. They do not implement real signing, replay protection, database access controls or distributed task transitions. No external service is contacted, no real credential is used, no model is called and no private result is transported. liveIntegrationVerified is false by design.

The actor/preparation is shared between the record/tool/handle branch and the separately granted memory/task/recipient branch. This does not implement a production bridge from arbitrary clinical records to memory, disclose private records to AI, or extend any current AI tool policy. Broad and write paths remain closed. Existing component behaviour is reused rather than credited again as new engineering layers; this layer owns only the joined executable proof and witness.

Foundation owns this proof and producer interfaces. AI owns current authenticated caller/proposal/tool-policy adapters and tool/model execution; L owns user/link/consent/read adapters; VC Integrations owns private registry, recipient transport and durable-task projections. Those actual paired consumer adapters and authenticated live execution/disclosure evidence remain open. The JSON witness records those gaps explicitly; separate chat rooms have not acknowledged them automatically.

All component checks remain point-in-time with no distributed transaction lock. The proof cannot certify callback read-only privileges, provider disclosure controls, cancellation after a final check or runtime transport enforcement. Real execution/disclosure needs current authority at its consumer boundary. No database, deployment, app UI, network transport or lifecycle endpoint is changed.
